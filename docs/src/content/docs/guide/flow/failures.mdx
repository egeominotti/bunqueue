## When a Child Fails

By default a parent just keeps waiting for its remaining children. Four child options change what happens when a child fails terminally: its last attempt fails, it throws `UnrecoverableError`, or stall detection, lock expiry or startup recovery after a crash uses up its attempts. The policy applies the same way on every path:

| Option | Behavior |
|--------|----------|
| `failParentOnFailure` | Parent immediately moves to `failed` (into the DLQ, error `Child job <id> failed: <error>`), even if other children are still running. Siblings are not cancelled and the parent's own attempts are not used |
| `removeDependencyOnFailure` | The failed child is silently dropped from the parent's dependencies; the parent proceeds as if it never existed |
| `ignoreDependencyOnFailure` | Like the above, but the failure is recorded; the parent can read it via `job.getIgnoredChildrenFailures()` |
| `continueParentOnFailure` | Parent is promoted to run **immediately**; `job.getFailedChildrenValues()` lists the failures recorded before it started, and it can cancel leftover children |

Choose at most one policy per child. A parent that `failParentOnFailure` moves to
`failed` has failed terminally too, so its own policy then applies to its parent:
`failParentOnFailure` on every level fails the whole branch up to the root. This
holds in every mode (in-memory, SQLite and PostgreSQL).

Policies are accepted only on a job that has a parent: `flow.add()` / `addBulk()`
children and `addBulkThen` parallel jobs. A root node, an `addChain` step or an
`addTree` child carrying one is rejected with `a flow failure policy requires a
parent`; in a chain, a step that fails terminally leaves the steps after it waiting.

With a persistent backend (SQLite or PostgreSQL), the selected policy and any
unresolved failure record are durable: a broker restart cannot reset the child to
default behavior or put an already-released parent back into `waiting-children`.

A worked example with `continueParentOnFailure`, useful when the parent should decide how to handle partial failure:

<Tabs syncKey="lang">
<TabItem label="Bun">

```typescript
import { FlowProducer, Worker } from 'bunqueue/client';

const flow = new FlowProducer({ embedded: true });

await flow.add({
  name: 'pipeline',
  queueName: 'main',
  data: {},
  children: [
    { name: 'step-a', queueName: 'workers', data: {}, opts: { continueParentOnFailure: true } },
    { name: 'step-b', queueName: 'workers', data: {}, opts: { continueParentOnFailure: true } },
    { name: 'step-c', queueName: 'workers', data: {} },
  ],
});

const worker = new Worker('main', async (job) => {
  const failed = await job.getFailedChildrenValues();
  // { 'workers:job-abc': 'step-a failed', ... }

  if (Object.keys(failed).length > 0) {
    await job.removeUnprocessedChildren();  // cancel direct children still queued
    return { status: 'partial', failedSteps: failed };
  }
  return { status: 'complete' };
}, { embedded: true });
```

<TabItem label="Python">

```python
from bunqueue import FlowProducer, Queue, Worker

flow = FlowProducer()
queue = Queue("main")

flow.add({
    "name": "pipeline",
    "queueName": "main",
    "data": {},
    "children": [
        {"name": "step-a", "queueName": "workers", "data": {},
         "opts": {"continue_parent_on_failure": True}},
        {"name": "step-b", "queueName": "workers", "data": {},
         "opts": {"continue_parent_on_failure": True}},
        {"name": "step-c", "queueName": "workers", "data": {}},
    ],
})

def process(job):
    failed = queue.get_failed_children_values(job.id)
    # {"workers:job-abc": "step-a failed", ...}

    if failed:
        queue.remove_unprocessed_children(job.id)  # cancel direct children still queued
        return {"status": "partial", "failed_steps": failed}
    return {"status": "complete"}

Worker("main", process).run()
```

And with `ignoreDependencyOnFailure`, when the parent should continue with partial data:

<Tabs syncKey="lang">
<TabItem label="Bun">

```typescript
import { Worker } from 'bunqueue/client';

const worker = new Worker('reports', async (job) => {
  const ignored = await job.getIgnoredChildrenFailures();
  // { 'workers:job-abc': 'enrichment API timeout' }
  return { partial: Object.keys(ignored).length > 0 };
}, { embedded: true });
```
